# Courses service

Owns self-paced courses and on-demand masterclasses, two genuinely different products sharing one data model (`Course.kind`), not two names for the same thing. A course is a structured, multi-lesson curriculum worked through at your own pace with lifetime access. A masterclass is a single focused session (or short arc from one event), usually sold as a time-limited replay (`Course.accessWindowDays`), not a permanent library addition. Both are presented distinctly: separate catalogue pages with distinct copy, a `FormatComparisonStrip` shown on both, and kind-aware framing on the sales page and enrollment card (see `src/components/courses/CourseSalesPage`, `CourseEnrollCard`).

Admin route: `/dashboard/admin/courses`. Member route: `/dashboard/my-learning/courses/[courseSlug]`. Free products enroll immediately. Paid products support Paystack and PayPal (M-Pesa Paybill was removed as a checkout option). A Parental Guidance course is also unlocked by an active Parent Membership, see `src/services/payments/parent-membership.ts`. Every online verification checks the signed-in learner, product reference, and exact server-side price before granting access.

Once a product has an enrollment, its curriculum is locked to protect lesson progress. Archive it and create a replacement when the lesson structure must change; catalog copy and pricing should be finalized before the first learner enrolls. Resaving a draft course (zero enrollments) deletes and recreates every lesson row, but an already-uploaded video or downloadable resource is carried forward automatically by matching on lesson id (see `nestedSections` in `course-service.ts`), so a routine edit never silently wipes them. The same carry-over keeps a video lesson's real, ffprobe-measured duration from being overwritten by a stale, hand-typed value on resave.

## Lesson video: self-hosted and protected, not a public embed

A lesson's `videoUrl` field (a plain iframe embed, e.g. YouTube/Vimeo) is a public URL with no relationship to purchase once someone inspects the page, the exact leak that let one purchase get shared freely. The recommended path for any paid video, especially a masterclass, is uploading it instead: `videoFileName` is stored under `COURSE_VIDEOS_STORAGE_DIR` (see `.env.example`), never `/public`, and streamed only through the enrollment-gated, Range-aware `/api/courses/lessons/[lessonId]/video` route, mirroring the teaching-video pipeline exactly (background ffmpeg compression via `src/services/courses/video-compression.ts`, `videoProcessingStatus` tracked the same way). `videoUrl` stays supported for existing content and is labeled "legacy, less secure" in the admin editor, never removed outright.

A self-hosted video also gets: a faint, persistent on-screen watermark of the viewer's name/email (a deterrent, not real DRM: a screen recording can still crop it out), `controlsList="nodownload"` on the `<video>` element, a course-level `accessWindowDays` the streaming route enforces on every request, and every successful stream logged to `CourseStreamEvent`. `src/services/courses/streaming-activity.ts` surfaces enrollments watched from an unusually high number of distinct IPs in the last 7 days at `/dashboard/admin/courses/[id]/activity`, where an admin can revoke one member's access outright. This is a signal for a human to judge, never an automatic cutoff: travel, VPNs, and mobile networks churn IPs for one honest buyer too.

Gate tests run with `npm test -- --runInBand`. Periodic product evals live in `evals/courses/` and verify the author-to-completion journey against the course contract.
